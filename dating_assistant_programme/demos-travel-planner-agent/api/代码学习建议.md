这是一个典型的 **FastAPI HTTP 封装层**：应用入口 → 请求模型 → SSE 工具 → 两条业务路由。按下面顺序读最快。

## 推荐阅读顺序

### 1. `main.py`（3 分钟）
先看清后端怎么启动、路由怎么挂上去。

- `app = FastAPI(...)`：`uvicorn api.main:app` 里的 `app` 就是它
- `CORSMiddleware`：放开跨域，方便前端本地联调
- `include_router`：挂上情感咨询、约会规划两套接口

读完就知道：**本文件夹不负责业务算法，只负责把 HTTP 请求接到 `agent` / `emotion` 服务。**

### 2. `schemas.py`（5 分钟）
看前端 JSON 长什么样。FastAPI 用这些 Pydantic 模型做校验，类型不对会直接 422。

| 模型 | 用在哪 | 关键字段 |
|------|--------|----------|
| `StreamRunRequest` | 约会规划运行 | `threadId`、`input`、`command` |
| `ResumeCommand` | HITL 恢复 | `resume`（用户对追问的回答） |
| `EmotionChatRequest` | 情感流式对话 | `threadId`、`message` |
| `EmotionBuildRequest` | 建向量索引 | `book_name`（可选） |

记住一点：约会规划同一会话的「开跑」和「回答中断」共用一个请求体，靠有没有 `command` 区分。

### 3. `sse.py`（10 分钟，关键）
流式接口和 HITL 恢复的核心胶水，三个函数都要懂：

| 函数 | 做什么 |
|------|--------|
| `sse(payload)` | 字典 → `data: {...}\n\n`（SSE 协议格式） |
| `stream_input(req)` | 请求体 → 图输入：新跑用 `{}`，恢复用 `Command(resume=...)` |
| `extract_interrupt_value(chunk)` | 从 LangGraph 输出块里抠出 `__interrupt__` 展示文案 |

一句话：`stream_input` 决定**怎么喂图**，`extract_interrupt_value` 决定**图停在哪、问用户什么**，`sse` 决定**怎么推给前端**。

### 4. `date_routes.py`（核心，约 20 分钟）
约会规划 HTTP 层。先看模块顶部编译图的两行：

```python
graph = builder.compile(checkpointer=MemorySaver())
threads: set[str] = set()
```

教学对照：`agent/graph.py` 里无 checkpointer 的 `graph` 只能跑通一遍；这里挂上 `MemorySaver` 后，HITL 才能跨 HTTP 请求暂停/续跑。

再按接口读：

```
POST /api/date/threads              → 创建 threadId
GET  /api/date/threads/{id}/state   → 查当前 state
POST /api/date/runs/stream-plan     → SSE 流式跑图（主路径）
POST /api/date/runs/invoke          → 非流式，结果一次性返回
```

`stream-plan` 建议对照事件类型理解：

| SSE `type` | 含义 |
|------------|------|
| `node` | 某节点刚跑完，前端可显示进度 |
| `interrupt` | 图在 HITL（Human-In-The-Loop，人工在环）处暂停，等待用户用 `command.resume` 字段带回答再次请求 |
| `final` | 整图跑完，`values` 里是最终方案 |
| `error` | 运行异常 |

辅助函数（`_config`、`_public_values`、`_timed_graph_stream`）遇到调用再跳进去看即可；耗时日志是教学观察用的，可后读。

#### 追问：`confirm_departure_hitl` 从哪里被触发？

`date_routes.py` **不会直接调用** `confirm_departure_hitl`，它是图跑完上一个节点后，沿边自动进入的。

**HTTP 入口**（二选一都会进图）：

1. `POST /api/date/runs/stream-plan` → `stream_plan_run`
2. `POST /api/date/runs/invoke` → `invoke_run`

两者都走到 `_timed_graph_stream` 里的：

```python
for chunk in graph.stream(
    stream_input(req),           # 新跑用 {}，恢复用 Command(resume=...)
    config=_config(req.threadId),
    stream_mode="updates",
):
```

**图中的边**（见 `agent/graph.py`）：

```
START → collect_date_details_hitl → confirm_departure_hitl → ask_preferences → ...
```

因此真正能进 `confirm_departure_hitl` 的时机是：`collect_date_details_hitl` 成功返回之后（用户已答完第一轮 HITL，地点/日期/时间段解析通过）。

**典型请求序列**：

1. 首次 `stream-plan` / `invoke`（无 `command.resume`）
   → 跑到 `collect_date_details_hitl` 的 `interrupt(...)` → 返回 interrupt，流结束
2. 再带同一 `threadId` + `command.resume=用户回答` 请求
   → 恢复第一轮 HITL → 节点返回成功
   → **图自动走到 `confirm_departure_hitl`**
   → 执行到 `nodes.py` 里 `interrupt(prompt)`，再发一次 interrupt（问出发地）

结论：从 `date_routes.py` 看，触发点就是 `_timed_graph_stream` 里的 `graph.stream(...)`；业务上是在「第一轮 HITL 答完并 resume」之后，由图边自动进入 `confirm_departure_hitl`。

### 5. `emotion_routes.py`（10 分钟）
情感咨询 HTTP 层，业务几乎全委托给 `emotion.service`：

```
POST /api/emotion/indexes/build     → 建/重建书籍向量索引
POST /api/emotion/threads           → 创建会话
POST /api/emotion/chat/stream       → SSE 流式对话（RAG）
GET  /api/emotion/reports/{id}      → 下载恋爱报告 PDF
```

读法：路由只做参数校验 + SSE/文件包装，真正逻辑在 `emotion/` 包；本文件保持「薄」。

### 6. `__init__.py`（可选）
包说明，知道模块职责划分即可。

---

## 一句话心智模型

> **`main` 挂路由 → `schemas` 验请求 → `sse` 做流式/HITL 胶水 → `date_routes` / `emotion_routes` 把 HTTP 接到图或服务；约会规划靠 `threadId` + checkpointer 跨请求续跑。**

若只想最快建立全局观：`main.py` → `schemas.py` → `sse.py` → `date_routes.py` 的 `stream_plan_run`，大约 30 分钟就能摸清「前端怎么驱动 LangGraph HITL」这条主链路。
