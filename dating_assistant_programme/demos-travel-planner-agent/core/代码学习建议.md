这是整个后端的 **共享基础设施层**：环境配置 → LLM 工厂。文件很少，按下面顺序读最快。

## 推荐阅读顺序

### 1. `settings.py`（10 分钟）
先看配置从哪来、有哪些键。导入本模块时就会：

1. 定位项目根目录 `PROJECT_ROOT`
2. `load_dotenv(.env)` 把密钥写进环境变量
3. 实例化只读单例 `settings`

重点记住字段分组（都对应 `.env`）：

| 分组 | 代表字段 | 谁在用 |
|------|----------|--------|
| 大模型 | `dashscope_api_key` / `qwen_model` / `qwen_base_url` | `core.llm`、各业务 LLM 调用 |
| 外部工具 | `tavily_api_key` / `amap_api_key` | `agent.clients`（搜索、地图） |
| 情感 RAG | `chroma_*` / `emotion_embed_*` / `emotion_similarity_top_k` | `emotion` 向量检索 |
| 会话记忆 | `redis_url` / `emotion_memory_*` | `emotion.memory` |
| 报告输出 | `emotion_reports_dir` | 恋爱报告 PDF 落盘 |

教学要点：
- `frozen=True`：配置对象不可变，避免运行时被误改
- 敏感信息不写死在代码里，缺省有合理默认值
- 其他模块统一：`from core.settings import settings`

### 2. `llm.py`（5 分钟）
只有一个工厂函数 `create_llm(**kwargs)`。

作用：按 `settings` 创建 `ChatOpenAI` 客户端，指向 DashScope 的 OpenAI 兼容接口。

为什么用 `langchain_openai.ChatOpenAI` 调通义千问？

> 改 `base_url` + `api_key` + `model` 即可，LangChain / LangGraph 的 `invoke` / `stream` / `with_structured_output` 都能直接用。

调用方需要流式或调温度时，通过 `**kwargs` 传入即可，例如 `create_llm(streaming=True)`。

### 3. `__init__.py`（可选）
包说明，知道「配置 + LLM 工厂」两件事即可。

---

## 一句话心智模型

> **`.env` → `settings` 收敛成只读单例 → `create_llm` 按配置造客户端；业务代码只依赖 `settings` / `create_llm`，不自己读环境变量、不自己拼模型参数。**

若只想最快建立全局观：扫一遍 `settings.py` 的字段分组，再看 `create_llm` 怎么把三项配置塞进 `ChatOpenAI`，大约 15 分钟就能摸清本文件夹。
